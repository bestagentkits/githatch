The Problem

Green tests, unproven contract

The Hatch Pet pipeline passes 81 Vitest + 35 determinism tests and builds cleanly, yet Kongming's autonomous review returned a formal NO-GO — twice: once on the implementation (12 blockers) and once on the first draft of this very plan (12 required edits, all folded in). Every passing check was mock-bound; none exercised the real Cloudflare Queue→Gemini→R2→D1→review→publish lifecycle, its failure modes, its cost controls, or the artifact that actually ships.

The decision is not whether the code compiles. It is whether an authenticated production claim can consume authentic telemetry, generate one immutable identity, survive queue duplication and partial failure without unbounded spend, reject corrupt or visually invalid assets, publish only cryptographically verified bytes, and deploy the same Worker that was tested.

This plan fixes every release blocker under strict TDD on real workerd bindings, honoring the binding AGENTS.md invariant #4: per-pose generation (one pose per API call composited locally) with contour bounding-box extraction, and content-addressed publication.

Implementation Workflow

Linear order, harness first

Definition of Done

Plan-level acceptance

  • Every blocker has a test with a captured RED baseline and a GREEN result; import/config failure is not blocker proof.
  • Real @cloudflare/vitest-plugin suite green on workerd; mock-only lifecycle test retired.
  • Invalid queue/manifest/identity JSON quarantines to DLQ; identity never synthesized (fails closed).
  • No fabricated telemetry; known SHA-256 vectors match Node↔workerd.
  • Transparent/collage(>4 components)/multi-subject(>30%)/malformed/oversized image, missing reference, altered frame/master — each prevents ASSET_READY.
  • Duplicate delivery converges to one accepted pose (at-least-once queue); post-crash spend bounded by per-job/day cap, reservations reconciled (reference + poses).
  • Worst-case consumer duration under a safety margin below 15 min.
  • Single atomic D1 pointer publication; no crash leaves mixed state; losers get a truthful conflict; readers resolve only the content-addressed manifest.
  • Reviewer identity hash server-derived; dedicated admin secret; constant-time; JWKS rotation; exact-bytes review evidence persisted.
  • One authoritative bundle (recorded SHA-256), deployed == tested, --env production on deploy+secrets, component-scoped hard secret gates, explicit max_concurrency.
  • Root AGENTS.md refreshed and reconciled via /ak:docs agent-context during Phase 7 to document the single-source deploy artifact, secrets pipeline, and zero-defect verification rules.
  • Isolated staging bootstrapped in P1; a full live hatch (reference + 16 poses) reaches ASSET_READY only after real human review at the named review route; digests agree.
  • Fresh Kongming verdict = GO, zero defects.
Resolved Decisions
  • Generation granularity (P4): per-pose fan-out (16 pose calls composited locally) per binding AGENTS.md #4; contour detection per frame, never fixed-slice.
  • Publication scheme (P5): content-addressed masters + content-addressed manifest, immutable-first, one D1-selected pointer.
  • Reviewer surface (P6/P8): in-repo authenticated route /auth/admin/review/:jobId behind Cloudflare Access; immutable bundle + explicit approve/reject; persisted reviewer principal, bundleSha, frame/manifest hashes, timestamp.
Open Questions
  • Gemini idempotency: a provider-side idempotency key would allow strengthening the external-charge invariant toward exactly-once; assumed absent (ledger+cap+reconcile is the ceiling).
  • Staging Gemini budget: confirm a capped key funds one full live hatch (reference + 16 poses); else P8 splits into a labeled canary + fixture smoke and GO is withheld until a full live hatch runs.
